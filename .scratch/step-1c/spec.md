# Step 1c: Claude Code Adapter (hooks, installer, `/stop-track`, JSONL tailer fallback, stale-turn timeout)

Status: ready-for-agent

Source: `docs/roadmap.md` (Step 1c), `docs/steps.md` (Step 1, Build item 4 "Claude Code" and the Codex stale-turn bullet), `docs/protocol.md` sections 1 and 2 (including "`FILE_MUTATION` attribution windows"), the 1b spec's Further Notes ("1c dependency: `PreToolUse`"), and the AGENTS.md invariants "Claude Code Hooks", "Zero Raw Content Persistence", "Zero LLM Trust Boundary", "`FILE_MUTATION` Attribution" and "Local Ingestion Bus Hardening".

Gate items this sub-step owns (from the Step 1 Exit Gate):

- [ ] Stopping the daemon does **not** block or error out Claude Code (`"onFailure": "continue"`). (The OpenCode half belongs to 1d.)
- [ ] Running `/stop-track` immediately halts recording; restarting the daemon resumes JSONL tailing from saved byte offsets with zero lost events. (Tray Pause belongs to 1e.)
- [ ] (Shared with 1d) Integration tests verify normalized event ingestion across realistic Claude Code fixtures, generated by running the real `claude` CLI with synthetic prompts on a throwaway repo (never the developer's own transcripts), with zero duplicate events and zero raw prompt text persisted in SQLite.

Gate evidence plan (agreed with the human at spec time):

- 3-OS CI covers every automated test below. There is **no** CI job that calls the Anthropic API.
- The "stopped daemon doesn't block Claude" item is proven in CI from the generated hook config itself: every Traction hook entry has a short `timeout` and fails open (never `onFailure: "block"`), and a test fires each generated entry, as Claude Code would, at a closed port and shows it fails fast on all 3 OSes.
- At sign-off the human runs a one-off local `claude -p` check with their own login, with the daemon stopped and then running.

## Problem Statement

After 1b, the daemon routes Traction Events to Projects and attributes file edits to Harness sessions, but no real Harness sends it anything. Claude Code, the most-used of the three v1 Harnesses, is invisible: a teen can spend an evening steering Claude through a hard bug and Traction records nothing except unattributed file edits, which it then wrongly credits as Manual Work.

Wiring Claude Code in has sharp edges:

- Claude Code hooks run inside the user's coding loop. A slow or stopped daemon must never freeze or error out Claude Code, so every hook must time out fast and fail open.
- The bearer token must reach the hooks without being written into `settings.json`, which users commonly share and commit.
- Hooks can't see what happened while the daemon was stopped, so turns from that gap are lost unless something reads Claude's own session transcripts. That reader must never double-count what hooks already delivered, and must resume exactly where it left off after a restart.
- Hook payloads and transcripts both carry raw prompt text, file contents and tool output. None of it may reach SQLite.
- Users need a way to stop tracking one session (`/stop-track`) without stopping the daemon. That must never block Claude's automated turns.
- 1b's hook window opens on `TOOL_PRE`, but the Claude hook list in `docs/steps.md` had no `PreToolUse` until now. Without it, Claude edits only get the coarse fallback attribution.
- 1b's log-tailed turn windows stay open until a turn end that a crashed or killed Harness never writes. An unterminated turn then claims every hand edit in that Project as the Harness's until the daemon restarts, which turns real Manual Work into Agent Compute.

From the user's point of view: "I run one install command and keep using Claude Code exactly as before. Traction sees my sessions, prompts and tool calls without ever storing what I typed. If the daemon is off, Claude doesn't notice, and Traction catches up from Claude's own logs when it comes back. `/stop-track` stops tracking this session instantly. When Claude crashes mid-turn, my own edits afterwards still count as mine."

## Solution

Add a **Claude Code Adapter** inside `traction-daemon`, plus an installer, plus one attribution fix:

- **Hook endpoint.** A new authenticated bus route accepts Claude Code's native hook payloads (same token, `Host` and `Origin` checks as `/v1/event`). The daemon maps each hook to a Traction Event with `harness_id: claude-code` and `attribution_source: harness_hook`, keeps only an allowlist of metadata fields (session ID, `cwd`, hook name, tool name, a few lengths and flags), computes `prompt_char_len` and `has_stacktrace` in memory, and drops the raw payload before anything is queued. It answers within the 1-second hook timeout.
- **Hook set.** `SessionStart`, `UserPromptSubmit`, `PermissionRequest`, **`PreToolUse`**, `PostToolUse`, `PostToolUseFailure`, `SubagentStart`, `SubagentStop`, `CwdChanged`, `DirectoryAdded`, `Stop`, `StopFailure` and `SessionEnd`. Never `WorktreeCreate`. `PreToolUse`→`PostToolUse`/`PostToolUseFailure` gives every Claude tool call an exact hook window, so Claude edits are attributed precisely.
- **`/stop-track` and `/resume-track`.** On `UserPromptSubmit`, a prompt that is exactly one of those commands flips that session's pause state and returns `{"decision": "block", "reason": "..."}`, so the command never reaches the model and is never stored. Every other prompt gets an empty, non-blocking answer. While a session is paused, none of its events (hook or tailed) are stored, but it still claims its own file edits, which are then dropped instead of being recorded as Manual Work.
- **Installer.** A `traction-daemon install claude-code` subcommand merges Traction's HTTP hooks into the user's Claude Code `settings.json`: `"timeout": 1`, `"onFailure": "continue"`, the token sent as `Authorization: Bearer $TRACTION_TOKEN` with `TRACTION_TOKEN` in `allowedEnvVars`. It keeps every non-Traction hook the user already has, is idempotent, refuses to touch a malformed file, and writes atomically. It always writes Traction's `stop-track.md` and `resume-track.md` custom commands into the Claude commands folder (`disable-model-invocation: true`, no instructions to the model), so Claude Code recognizes both commands and the hook blocks them before any model call. It checks `claude --version` and warns (but still installs) below v2.1.295, where `onFailure` is not supported. It adds a marked block to the user's shell profiles that exports `TRACTION_TOKEN` by reading `~/.traction/daemon.token` at shell start, so the token value is never copied into any config file (Windows also gets a per-user environment variable).
- **JSONL tailer fallback.** The daemon tails Claude Code session transcripts (`<claude config dir>/projects/<project-slug>/<session-id>.jsonl`, preferring the `transcript_path` a hook reports) by file identity and byte offset. It maps transcript records to Traction Events with `attribution_source: harness_log`, computing the same in-memory metrics and discarding raw text. It emits only records that hooks did not cover (sessions with no working hooks, and spans when the daemon was down), with deterministic event IDs, and persists offsets in the same transaction as the events it emitted. After a restart, nothing is lost and nothing is stored twice.
- **Stale-turn timeout.** Any open Attribution Window, either a log-tailed turn window or a hook window (an open tool call inside an open turn), stops covering mutations once its session has produced no event for `STALE_TURN_TIMEOUT` (**10 minutes**). The rule is checked lazily when a mutation is attributed. A crashed, `kill -9`ed or unterminated turn or tool call stops claiming Manual Work instead of holding until a daemon restart. This is shared attribution logic: Claude hooks and the Claude tailer use it now, and the OpenCode plugin and Codex tailer (1d) get it for free.

When 1c is done, running `traction-daemon install claude-code` and opening a new shell is enough for every Claude Code session to appear in SQLite as content-free Traction Events, routed to the right Project, with Claude's edits attributed to Claude and the user's own edits to them.

## User Stories

**Installing**

1. As a user, I want one command to wire Claude Code into Traction, so that setup takes seconds and needs no manual JSON editing.

5. As a user, I want the installer to refuse, with a clear message, to touch a `settings.json` it cannot parse, so that a typo of mine is never overwritten.
6. As a user, I want `settings.json` written atomically, so that a crash mid-install never leaves a half-written file that breaks Claude Code.
7. As a user, I want my original `settings.json` copied to a one-time backup before Traction first edits it, so that I can always get back to where I was.
8. As a user, I want `settings.json` created if it doesn't exist yet, so that a fresh Claude Code install works too.
9. As a user who sets `CLAUDE_CONFIG_DIR`, I want the installer and tailer to use that folder instead of `~/.claude`, so that my non-default setup is tracked.
10. As a user, I want the installer to warn me when my Claude Code is older than v2.1.295 but still install, so that I know `onFailure` isn't honoured, while older versions stay non-blocking by default.
11. As a user without the `claude` CLI on my `PATH`, I want the installer to say it couldn't check the version and still install, so that a missing binary doesn't block setup.
12. As a user, I want my bearer token never written into `settings.json`, so that sharing or committing my Claude settings never leaks it.
13. As a user, I want the installer to add a clearly marked block to my shell profile that reads the token file when the shell starts, so that `TRACTION_TOKEN` is set in every new terminal without the token being copied anywhere.

16. As a user, I want the installer to tell me to open a new shell (or restart Claude Code) for hooks to authenticate, so that I know why the first session in an old shell is tailer-only.

**Never getting in Claude's way**

23. As a user, I want the daemon to never return a blocking decision except for my exact `/stop-track` or `/resume-track` command, so that Traction never blocks a prompt or tool call of mine or of an automated turn.

## Implementation Decisions

**Modules**

- `traction-daemon` gains a **Claude Code Adapter** module with three parts behind one internal interface:
  - *hook mapping*: native hook payload → zero or one Traction Event plus an optional hook response;
  - *transcript mapping*: one transcript record → zero or more Traction Events;
  - *transcript tailer*: discovers, reads and resumes transcripts, then hands records to the mapping.
  The mapping parts are pure (bytes in, events out, raw text dropped inside), so the same content-free metric code serves hooks and transcripts.
- The bus gains one route; the Router gains session pause state and the "hook-covered" bookkeeping; attribution gains the stale-turn rule; storage gains new tables through new migrations (shipped migrations are never edited).
- The installer is a new subcommand of the existing `traction-daemon` binary. (A separate `traction` CLI arrives in 1e; the installer can move behind it then.)
- No new protocol fields: everything fits `schema_version: 1` as it stands.

**Hook endpoint**

- Route: `POST /v1/hooks/claude-code`. Same `Host`, `Origin` and bearer-token checks, same error codes and same Unix-socket rules as `/v1/event`.
- Body cap for this route only: **8 MiB** (hook payloads can embed large tool output). The body is parsed into an allowlisted struct (unknown fields ignored, large values not kept), then the buffer is dropped. Over the cap: `413`, which Claude Code treats as a non-blocking hook error.
- The hook name comes from `hook_event_name`. Mapping (all `harness_id: claude-code`, `attribution_source: harness_hook`, `network_class: cloud_api`):

  | Hook | Traction Event | Kept metadata |
  |---|---|---|
  | `SessionStart` | `SESSION_START` | `cwd`, `model_id` if present |
  | `UserPromptSubmit` | `PROMPT_SUBMIT` | `prompt_char_len`, `has_stacktrace` (computed, then text dropped) |
  | `PermissionRequest` | `PERMISSION_REQUEST` | `tool_name` |
  | `PreToolUse` | `TOOL_PRE` | `tool_name` |
  | `PostToolUse` | `TOOL_POST` | `tool_name` |
  | `PostToolUseFailure` | `TOOL_FAIL` | `tool_name` |
  | `SubagentStart` / `SubagentStop` | `SUBAGENT_START` / `SUBAGENT_STOP` | — |
  | `CwdChanged` | `CWD_CHANGE` | new `cwd` |
  | `DirectoryAdded` | none (registers the folder as a Project, as `/v1/project` does) | — |
  | `Stop` | `TURN_END{completed}` | — |
  | `StopFailure` | `STOP_FAILURE` | — |
  | `SessionEnd` | `SESSION_END` | — |
  | anything else | none | — |

- `repo_symbol_hits`, `exit_code` and `diff_lines_delta` stay `null` (Step 2 signals). `tool_name` is capped at the core identifier length.
- `event_id` is a fresh UUIDv7; `timestamp_ms` is the daemon's receive time (hook payloads carry no timestamp).
- A hook missing `session_id` or `hook_event_name`, or not JSON: `200 {}` with nothing stored. A Claude hook is never told to block because of a parse problem.
- Response: `200 {}` for everything except the `/stop-track`/`/resume-track` case. The answer is sent once the event is queued to the Router, never after a SQLite commit. A full Router queue answers `200 {}` and drops the event (the tailer covers it later only if the session is not hook-covered; this loss is accepted and counted in the daemon log).
- A `transcript_path` in any hook is remembered for that session only if it canonicalizes to a file under the Claude projects folder; otherwise it is ignored.

**Pause (`/stop-track`, `/resume-track`)**

- Match: the `UserPromptSubmit` prompt, trimmed of surrounding whitespace, equals exactly `/stop-track` or `/resume-track`, or equals exactly the body text of the matching Traction command file (in case a Claude Code version hands the hook the expanded command). The hook endpoint and the installer share one definition of that text. No other hook, and no other prompt, can pause.
- Response: `{"decision": "block", "reason": "Traction tracking paused for this session."}` (or "Traction tracking resumed for this session.") with no Traction Event stored for that prompt. Repeating a command is idempotent and gives the same answer.
- Pause is per `(harness_id, session_id)` and stored as spans (`from_ms`, nullable `to_ms`) in a new SQLite table through the single writer, so it survives restarts. The Router reads the open spans at startup.
- While a session is paused, its events (hook or tailed) are not stored, but they still feed the attribution windows. A `FILE_MUTATION` claimed by a paused session is dropped. A mutation outside every window is still Manual Work as usual.
- The tailer drops records whose timestamp falls in a paused span of their session.
- The block answer is what keeps the command from reaching the LLM: Claude Code drops a prompt that `UserPromptSubmit` blocks. If the daemon is down, the hook fails open and the custom command's harmless body reaches the model, which is acceptable: that body carries no instructions and the session isn't being tracked anyway.
- Verification task: with the real `claude` CLI (v2.1.332 on the dev machine) and the installed command files, confirm which text `UserPromptSubmit` receives for `/stop-track` (literal or expanded) and that the block answer stops the model call. Record the finding in the ticket, in the fixtures and in `docs/protocol.md`.

**Installer (`traction-daemon install claude-code`)**

- Options for hermetic tests: `--settings <path>` (default `<claude config dir>/settings.json`), `--claude-program <path>` (default `claude` on `PATH`), `--profile <path>` (repeatable; default: the user's existing zsh, bash, fish and PowerShell profiles), `--port <n>` (default 41937).
- Claude config dir: `$CLAUDE_CONFIG_DIR` if set, else `~/.claude`. The tailer uses the same rule.
- Each Traction hook entry, one per hook in the hook set, under the hook's event key:
  `{"type": "http", "url": "http://127.0.0.1:41937/v1/hooks/claude-code", "timeout": 1, "onFailure": "continue", "headers": {"Authorization": "Bearer $TRACTION_TOKEN"}, "allowedEnvVars": ["TRACTION_TOKEN"]}`
  in a matcher group that matches all tools for the tool hooks.
- Traction ownership: an entry is Traction's when its `url` is the Traction hook URL on any port. A merge removes every Traction entry and then adds the current set, leaving all other entries and keys untouched (key order kept as far as the JSON library allows). Result: idempotent, and upgrades replace instead of duplicating.
- Refuses (non-zero exit, file untouched) when `settings.json` isn't valid JSON or its `hooks` value isn't an object. Never writes `WorktreeCreate`, and removes a Traction-owned `WorktreeCreate` entry if one is found.
- Writes via temp file + rename in the same folder. Before the first Traction edit, copies the original to `settings.json.traction-backup` (never overwritten later).
- Command files: always writes `<claude config dir>/commands/stop-track.md` and `resume-track.md`. Each has YAML frontmatter with a `description` and `disable-model-invocation: true` (so the model can never run it through the slash-command tool), followed by a one-line body naming the Traction action, with **no instructions to the model** (Zero LLM Trust Boundary). Each file carries a Traction marker comment. A file is overwritten only when it is missing or carries the marker. A user-written file with the same name is left untouched, and the installer warns that `/stop-track` will rely on the literal-text match only.
- Version check: runs `<claude-program> --version` with a 5-second kill timeout. Below `2.1.295`: warning, install continues. Unparseable output or missing program: "could not check Claude Code version" warning, install continues.
- Token env: on Unix, appends to each profile a block between `# >>> traction >>>` and `# <<< traction <<<` that exports `TRACTION_TOKEN` from the token file at shell start (fish and PowerShell get their own syntax). Rerunning replaces the block instead of adding one. On Windows, also sets `TRACTION_TOKEN` under the user's `HKCU\Environment` (no admin). The token value never goes into `settings.json`.
- Prints a summary: settings path, hooks installed, version warning if any, profiles touched, and "open a new terminal (and restart Claude Code) so hooks can authenticate".
- Never requests admin/UAC and never touches anything outside the files named above.

**Transcript tailer**

- Watches `<claude config dir>/projects/` recursively with OS notifications (no idle polling) and reads `<project-slug>/<session-id>.jsonl` files. Subagent transcript files are not tailed (`SubagentStart`/`SubagentStop` hooks cover subagents).
- Per file it stores `(path, file identity, byte offset)` in a new SQLite table. File identity is inode + device on Unix and the volume serial + file index on Windows. Windows opens use `FILE_SHARE_READ | FILE_SHARE_WRITE | FILE_SHARE_DELETE`.
- Reads only complete lines (up to the last `\n`). Identity change or size < offset → reread from 0. Bad JSON line → skipped and logged by reason code only.
- First sight of a file: if it existed before the daemon's first-ever tailer start (recorded once), start at its end; otherwise start at 0.
- Record mapping (`attribution_source: harness_log`, `session_id` from the record's `sessionId`, `cwd` from the record):
  - first mapped record of a session the daemon has never stored a `SESSION_START` for → `SESSION_START`;
  - `user` record with prompt text (not a tool result, not a meta/command record) → `PROMPT_SUBMIT` (metrics computed, text dropped);
  - `tool_use` block in an `assistant` record → `TOOL_PRE` (`tool_name`);
  - `tool_result` block in a `user` record → `TOOL_POST`, or `TOOL_FAIL` when it is an error;
  - an explicit API-error record → `STOP_FAILURE`, and an explicit turn-end record → `TURN_END`, **only if** the real fixtures show such records. Otherwise a tailed turn ends at the next prompt or by the stale-turn timeout. Record what the fixtures show in the ticket.
  - every other record type → nothing.
- `timestamp_ms` from the record's ISO timestamp. `event_id` is deterministic: a UUID-formatted SHA-256 of `("claude-code", session_id, record uuid, block index, event type)`, so rereads are absorbed by the existing `INSERT OR IGNORE` on `event_id`.
- Offsets are committed in the same writer transaction as the events read up to that offset (the writer gets a "tailer batch" message carrying both).
- **Hook coverage (dedup rule).** The daemon stores a run row for each daemon start (`started_ms`, `last_alive_ms` bumped on every writer commit) and, per session and run, the timestamp of the first accepted hook event (`first_hook_ms`). A tailed record is dropped when its timestamp is within `[first_hook_ms, last_alive_ms]` of any run for its session (the current run's span is open-ended). Everything else is emitted: sessions whose hooks never authenticated, records from before the first hook of a run, and records from spans when the daemon was down. A tailed `SESSION_START` is also dropped if one is already stored for that session.
- Tailed events from the past go through the Router like any other event. They can't claim live mutations (attribution is live-only and windows compare timestamps), and the stale-turn rule closes any turn they leave open.

**Stale-turn timeout (attribution)**

- `STALE_TURN_TIMEOUT` = **10 minutes**, public in `traction-daemon` next to `LOG_TAIL_HOLD`, `LOG_TAIL_TRAILING_WINDOW` and `WINDOW_CLOSE_GRACE`, with a test-only override in the watcher settings. It is 10 minutes because a single healthy tool call (Claude's longest `Bash` timeout is 10 minutes) can be that quiet.
- Rule: an **open** hook window or log-tailed turn window covers a mutation at `t` only if the session's latest event timestamp at decision time is ≥ `t − STALE_TURN_TIMEOUT`. Equivalently, an open window effectively ends at `last_event_ms + STALE_TURN_TIMEOUT`. Any event from the session (any type, any source) counts as activity. It is checked lazily in `claim` when a held mutation is decided, so no timer thread is needed.
- Closed windows are unchanged: they still end at their closing event plus `WINDOW_CLOSE_GRACE`. A stale hook turn (`PROMPT_SUBMIT` with no turn end) needs no extra rule, because it claims nothing without an open tool call. A new `TOOL_PRE` from the session counts as activity, so it opens a fresh window as before.
- `docs/protocol.md` ("`FILE_MUTATION` attribution windows") and `GLOSSARY.md` ("Attribution Window") are updated in the same ticket.

**Storage (new migrations)**

- `session_pause (harness_id, session_id, from_ms, to_ms)`.
- `transcript_offset (path PRIMARY KEY, file_identity, offset, updated_ms)` plus a one-row marker for the tailer's first-ever start.
- `daemon_run (run_id, started_ms, last_alive_ms)` and `session_hook_run (harness_id, session_id, run_id, first_hook_ms)`.
- All writes go through the single writer. `traction_event` stays append-only and unchanged.

## Testing Decisions

Good tests here drive the daemon only through its public surfaces (the bus, the binary, files on disk) and assert on observable results: HTTP answers, rows in SQLite read through a read-only connection after shutdown, and file contents. They never reach into module internals or assert on private state.

Seams (agreed with the human):

- **Seam A: in-process daemon (existing).** A real daemon on a temp data folder, a fake home and an ephemeral port, driven over HTTP/the Unix socket, with SQLite read after shutdown. New config points the tailer at a temp Claude config folder under the fake home. It covers:
  - Hook mapping for every hook in the set, using captured real payloads, including unknown-field tolerance, the 8 MiB cap, malformed bodies (`200 {}`, nothing stored) and auth/Host/Origin refusals on the new route.
  - Canary test: payloads and transcripts full of canary strings (prompt, tool input/output, file content) leave none in SQLite.
  - `PreToolUse`→`PostToolUse` hook windows attributing a real watcher mutation to `claude-code`, and a mutation between tool calls staying Manual Work.
  - `/stop-track` / `/resume-track`: exact-match only, block response, nothing stored while paused, paused-session mutations dropped, pause surviving restart, idempotent repeats.
  - Tailer: tailer-only session fully recorded; partial lines; replaced and truncated files; malformed lines; pre-existing files started at end; restart resumes from saved offsets with zero lost and zero duplicate events (stop daemon, append records, restart).
  - Dedup: the same session sent both as hooks and as a transcript yields one set of events. Records from a "daemon down" span are filled in from the transcript.
  - Forged `transcript_path` outside the Claude folder is ignored.
  - Stale-turn: a log-tailed turn with no events for the overridden `STALE_TURN_TIMEOUT` stops claiming a later mutation (Manual Work), and so does an open hook window (`TOOL_PRE` with no `TOOL_POST`, as after `kill -9`). A turn or tool call kept alive by events still claims it.
- **Seam B: the daemon binary (existing, `binary.rs` style).** Runs `traction-daemon install claude-code` against temp `settings.json` and profile files with a fake `claude` program printing chosen versions. It covers:
  - Merge preserves foreign hooks and keys, is idempotent, replaces old Traction entries, never writes `WorktreeCreate`, refuses malformed JSON untouched, writes the backup once, creates a missing file.
  - Every generated Traction entry has `timeout` ≤ 1, `onFailure: "continue"` (never `"block"`), the `$TRACTION_TOKEN` header with `TRACTION_TOKEN` in `allowedEnvVars`, and no token value anywhere in the file.
  - **Fail-open firing test:** for each generated entry, issue the request it describes (its URL with the port swapped for a known-closed one, its headers, its `timeout`) and assert it fails within `timeout` + a small margin, on all 3 OSes.
  - Command files: both written with `disable-model-invocation: true` and no model instructions, rewritten on rerun, user-written files of the same name left untouched with a warning. The matching Seam A test sends the literal command and the file's body text to `UserPromptSubmit` and gets the block answer for both.
  - Version warnings: old version, new version, unparseable output, missing program.
  - Profile block: added once, replaced on rerun, reads the token file rather than containing the token.
- Pure unit tests are allowed inside the Adapter module only where Seam A would be very slow or impossible to set up (for example, exhaustive stack-trace detection cases). Prefer Seam A.
- **Fixtures:** a capture script runs the real `claude -p` CLI with synthetic prompts on a throwaway Git repo while a capturing HTTP listener records hook payloads, then copies the session transcript. This is run by a human or agent locally, never in CI and never on real transcripts. Fixtures are committed under the daemon's test data with the Claude Code version they came from. Scenarios: normal multi-tool session, tool failure, permission request, subagent, `cwd` change, interrupted turn, API-error stop (simulated if it can't be triggered).
- **Prior art:** `tests/attribution.rs` and `tests/watcher.rs` (windows and mutations), `tests/ingestion.rs` and `tests/request_checks.rs` (bus routes and refusals), `tests/persistence.rs` and `tests/binary.rs` (restart and binary behaviour), `tests/common` (daemon harness, fixtures, `poll_until`).
- All tests run on the existing 3-OS CI matrix. No test calls the Anthropic API.

## Out of Scope

- OpenCode plugin and poller, Codex rollout tailer (1d). 1d only reuses the stale-turn rule and the tailer's offset/identity storage pattern.
- Tray, hotkey, `traction pause`/`resume`, a separate `traction` CLI, auto-start, RSS/CPU measurement (1e). The tailer must avoid idle polling so 1e's budget holds.
- `traction --dry-run` for the installer (future polish, see roadmap), `traction doctor` and `traction uninstall` (Step 5 polish). The marked blocks and the backup are designed so uninstall can remove them later.

- Detecting local-model Claude Code setups (for example `ANTHROPIC_BASE_URL` pointing at a local server) and setting `network_class: local_model`. 1c always sends `cloud_api`; revisit in Step 2.

- A Codex `notify` wrapper (never in v1), and any harness beyond the three v1 ones.
- Any CI job that calls the Anthropic API.

## Further Notes

- **`kill -9` mid-tool:** a hard-killed Claude Code leaves a hook window open with no closing event. `STALE_TURN_TIMEOUT` bounds it: edits more than 10 minutes after the session's last event are Manual Work. Edits inside those 10 minutes still go to Claude. This is the accepted cost of not cutting off healthy long tool calls.
- **Roadmap wording:** the roadmap's 1c row describes the stale-turn timeout for log-tailed Harnesses only. 1c extends the same constant to hook windows. Update that row (and the `steps.md` stale-turn bullet) in the stale-turn ticket.
- **Hook-coverage assumption:** the dedup rule trusts that, once a session's hooks authenticate in a run, they keep delivering for the rest of that run. A hook dropped mid-run (full Router queue, a later `401`) is lost, not filled from the transcript. This trade keeps duplicates at zero, which the gate requires.
- **Clock skew:** hook timestamps are daemon receive times; transcript timestamps are Claude's write times on the same machine. Records within about a second of a hook-coverage boundary are the likeliest edge case; tests should include one.
- **Docs to update in the tickets that change them:** `docs/protocol.md` (the hook route, its cap and responses, pause semantics and the command-file text match, `STALE_TURN_TIMEOUT` for hook and log-tailed windows, the `/stop-track` verification finding), `GLOSSARY.md` (Attribution Window stale rule; consider a "Session Pause" entry), and `docs/steps.md` only if a gate item's wording changes.
- **Step 1 Exit Gate wording:** the gate says "restarting the daemon resumes JSONL tailing from saved byte offsets". 1c delivers that for Claude transcripts; 1d must deliver the same for Codex rollouts before the item is ticked.
- Sign-off evidence: 3-OS CI run link, plus the human's one-off local `claude -p` check (daemon stopped: Claude unaffected; daemon running: events appear, `/stop-track` pauses).
